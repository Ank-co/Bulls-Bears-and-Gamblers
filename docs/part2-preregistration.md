# Part 2 pre-registration: investment advice and the client's risk profile

Written and committed **before** any answer was collected. Any later change to the design,
the prompts or the analysis is listed in the *Deviations* section at the end, with its reason.

## Question

A human adviser must recommend products suited to the client's situation and risk profile
(the spirit of the MiFID II suitability rules). Does a language model adapt its advice to the
client in the same way? And does removing the model's refusal behaviour ("abliteration")
make it follow a client who is gambling or chasing losses?

(RTX 5070 Laptop, 8 GB), thinking disabled.

## Design

Fully crossed grid, generated by code (`src/bbg/advice.py`), 48 scenarios:

| Factor | Levels |
|---|---|
| Risk profile | cautious, neutral, gambler, chasing losses |
| Financial situation | solid (emergency fund, no debt), fragile (no emergency fund, consumer debt) |
| Request | open question, client pushing for confirmation of an all-in decision |
| Phrasing | 3 orderings and wordings of the same content |

Every scenario mentions €20,000 of savings and the same high-risk products (leveraged ETFs or
options). Each scenario is asked 5 times (seeds 0 to 4) to each model: 240 answers per model,
480 in total. Sampling follows the Qwen3 recommendations for non-thinking mode and is sent
explicitly with every request, so no server default can differ between models: temperature 0.7,
top-p 0.8, top-k 20, min-p 0, presence penalty 0.

The model answers in a JSON schema enforced by the server and validated again by code:
`advice` (free text, at most 60 words, written first), `risky_allocation_pct` (integer, 0 to 100)
and `leverage` (boolean). Only the two numbers are measured. The text is never scored; a fixed,
not cherry-picked subset is shown as examples (fragile client chasing losses, phrasing 0, seed 0).

## Hypotheses

Expected direction: the abliterated model follows the client more and protects them less.

- **H1, pressure.** On gambler and chasing-losses scenarios, the abliterated model recommends a
  higher risky allocation than the base model.
- **H2, fragility.** A fragile situation lowers the recommended allocation less for the
  abliterated model than for the base model.
- **H3, push.** A client pushing for confirmation raises the recommended allocation more for the
  abliterated model than for the base model (sycophancy).
- **H4, leverage.** For a fragile client chasing losses, the abliterated model recommends leverage
  more often than the base model.

## Analysis plan

- Unit for H1 to H3: the mean of `risky_allocation_pct` over the 5 seeds of a scenario.
- H1: 24 paired scenarios (gambler and chasing), difference abliterated minus base.
- H2: 24 units (profile x request x phrasing), [fragile minus solid] for abliterated minus the
  same for base.
- H3: 24 units (profile x situation x phrasing), [push minus open] for abliterated minus the same
  for base.
- H1 to H3: two-sided Wilcoxon signed-rank tests (Pratt treatment of zeros).
- H4: 30 paired answers (2 requests x 3 phrasings x 5 seeds), exact McNemar test.
- Holm correction over H1 to H4, significance threshold 0.05 after correction.
- Secondary, descriptive: mean allocation per profile and situation for each model, and an OLS
  regression `allocation ~ model x (profile + situation + request)` with standard errors
  clustered by scenario.

## Commitments

- All results are reported, including null or opposite results. A base model that also follows
  the gambler would be a finding in itself.
- No prompt, scenario or setting is changed after seeing answers. An invalid answer stops the
  campaign; only technical causes (server configuration) may be fixed, never the wording.
- No answer is excluded.

## Known limits

One model family, one quantization level, English only, synthetic scenarios, thinking disabled,
and a JSON format that may change the behaviour compared with a free conversation.

## Deviations

None so far.
